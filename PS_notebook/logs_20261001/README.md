# 2026-10-01 板上并发定时重测（rt_sched.c）

板卡 ZCU104（PYNQ 3.0.1，Linux 5.15.19-xilinx，非 PREEMPT_RT），比特流为仓库重建的 `mpcc_r.bit`，
重放数据为原 H6 的 `frames.bin`（13 998 拍）/ `bufs.bin`（34 缓冲）/ `waves.bin`（2 721 窗），每次 20 s。
每个 `*_summary.csv` 是 `rt_sched` 的原始输出（逐拍的 `*_mpcc.csv` 约 10 MB，留在板上未入库）。

| 文件 | 调度 | 程序版本 | 控制迟到 | 估计迟到 | 检测迟到 |
|---|---|---|---|---|---|
| `rt_sched_other` | SCHED_OTHER（与 9 月 5 日原测量相同） | 无握手 | 9 / 400 001 | 0 | 0 |
| `rt_sched_fifo_run1..3` | SCHED_FIFO 80 + mlockall | 无握手 | 0 / 0 / 0 | 0 / 0 / 31 | 0 |
| `rt_fifo_p1..5` | 同上，每次前 `sync` + 空闲 10 s | 无握手 | 0（5 次） | 455 / 0 / 0 / 0 / 131 | 0 / 0 / 0 / 0 / 1 |
| `rt_other_h` | SCHED_OTHER | 启动握手 | 0 | 0 | 0 |
| **`rt_fifo_h1..5`** | **SCHED_FIFO 80 + mlockall，每次前 `sync` + 空闲 10 s** | **启动握手** | **0（5 次，共 2 000 005 次释放）** | **0（共 400 005）** | **0（共 5 005）** |

- 原测量（9 月 5 日，`reproducibility/` 归档）为普通优先级，控制拍 124 / 400 001 次迟到，全部来自操作系统抢占
  造成的释放等待（最长 1.71 ms）。实时优先级下 13 次重放（5 200 013 次控制释放）无一迟到，最大响应 48.5 µs。
- 无握手版本里估计 / 检测线程的迟到全部出现在第 0 次释放：`mlockall(MCL_FUTURE)` 使线程栈在创建时预取页，
  第二、三个线程启动晚于公共释放原点 T0（最长 105 ms），随后逐拍追赶被记为迟到。这是测试程序的启动假象，
  不是稳态调度行为；`rt_sched.c` 现在等三个线程都完成绑核和设优先级后再设 T0（`ready_wait`）。
- 论文定时表取 `rt_fifo_h1..5` 五次重放：中位数与 99 分位取五次中的最大值，最大值与迟到计数覆盖全部五次。
- 复现：`sudo ./run_rt_sched.sh <数据目录> 20 <输出前缀> 80`（脚本在运行期间关闭实时节流
  `kernel.sched_rt_runtime_us=-1`、把可迁移中断移到核 0，结束后恢复）。
